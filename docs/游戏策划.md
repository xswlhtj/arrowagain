## 1. 项目概述

### 1.1 项目名称

暂定名：**箭途 / Arrow Escape**。

### 1.2 一句话玩法

玩家观察棋盘上每支箭头的朝向，按正确顺序点击：前方没有其他箭头时，箭头飞出棋盘；前方被阻挡时，箭头碰撞返回并消耗一次失误机会。清空棋盘即可过关。

### 1.3 开发目标

使用 Python 和 Pygame 完成一个可运行、可解释、可测试的“一箭又一箭”风格小游戏，优先保证课程要求中的基础功能完整、核心逻辑正确和 3 个关卡确实可通关。

### 1.4 技术选型

| 项目 | 选择 | 原因 |
|---|---|---|
| 语言 | Python 3.10+ | 满足作业要求，开发和测试成本低 |
| 主图形库 | Pygame 2.x | 提供窗口、事件、鼠标、字体、图元绘制、动画计时和音频能力 |
| Pygame 模块 | `display`、`event`、`mouse`、`draw`、`font`、`time`；可选 `mixer` | 基础版不需要额外 GUI 框架或图片处理库 |
| Python 标准库 | `dataclasses`、`enum`、`copy`、`pathlib`；关卡外置时使用 `json` | 定义模型、方向、深拷贝、资源路径和数据加载 |
| 测试 | Python `unittest`（规则单元测试）+ 手工测试（界面流程） | 无需额外测试依赖，核心规则可脱离界面验证 |
| 数据格式 | Python 常量或 JSON | 关卡数据与游戏逻辑分离，便于扩展 |
| 版本管理 | Git + GitHub | 满足课程提交要求并保留真实开发过程 |

建议 `requirements.txt`：

```text
pygame>=2.5,<3
```

自动化测试使用 Python 标准库 `unittest`，因此运行时只需安装 Pygame。

### 1.5 范围边界

本版本必须实现：四方向单格箭头、鼠标点击、直线路径检测、成功飞出、碰撞反馈、**每关固定 3 次失误机会**、重开、至少 3 关、开始/游戏/结果界面。

首版暂不实现：复杂机关、多格箭头、斜向移动、联网、排行榜、账号系统、关卡编辑器、随机生成、自动求解和存档。附加功能只能在基础版全部验收通过后开发。

## 3. 核心游戏规则

### 3.1 坐标与方向约定

- 棋盘使用二维网格，左上角为 `(row=0, col=0)`。
- `row` 向下递增，`col` 向右递增。
- 每个格子最多放置一支箭头。
- 方向向量固定为：

| 方向 | 显示 | `dr` | `dc` |
|---|---:|---:|---:|
| UP | ↑ | -1 | 0 |
| DOWN | ↓ | 1 | 0 |
| LEFT | ← | 0 | -1 |
| RIGHT | → | 0 | 1 |

### 3.2 阻挡判定

箭头是否被阻挡只与**当前仍存在的箭头位置**有关，与其他箭头的朝向无关。

1. 从被点击箭头的下一格开始，沿 `(dr, dc)` 每次移动一格。
2. 尚未越过棋盘边界时：
   - 若该格存在箭头，立即判定为“被阻挡”；
   - 若为空，继续向前检查。
3. 扫描到边界之外仍未发现箭头，判定为“可以飞出”。

不构成阻挡的情况：箭头后方、斜对角、同行但位于反方向、同列但位于反方向的箭头。

### 3.3 点击结果

| 点击对象/状态 | 结果 |
|---|---|
| 空白区域 | 无效果，不扣失误次数 |
| 可飞出箭头 | 播放飞出动画；动画完成后移除；刷新剩余数 |
| 被阻挡箭头 | 播放碰撞反馈；失误次数减 1；箭头保留 |
| 动画播放中 | 暂停接受棋盘点击，避免重复结算 |
| 已通关或已失败 | 禁止继续操作棋盘，只允许结果界面按钮 |

### 3.4 胜负与优先级

- 一支箭头移除后，若剩余箭头数为 0，则本关胜利。
- 一次错误点击扣减后，若剩余失误次数为 0，则本关失败。
- 单次点击不会同时造成“移除箭头”和“扣失误”，因此胜负条件不会冲突。
- 最后一关清空后进入“全部通关”状态，不再尝试访问不存在的下一关。

## 4. 玩家流程与状态机

```text
程序启动
   ↓
[START 开始界面] ──点击开始──> [PLAYING 游戏中]
                                │       │
                     清空棋盘──┘       └──失误归零
                         ↓                    ↓
                 [LEVEL_CLEAR]           [FAILED]
                  │          │               │
          下一关──┘          └──最后一关     ├──重试本关──> [PLAYING]
              ↓                    ↓          └──返回首页──> [START]
          [PLAYING]          [ALL_CLEAR]
                                 │
                    再玩一次/返回首页
                                 ↓
                              [START]
```

建议状态枚举：`START`、`PLAYING`、`LEVEL_CLEAR`、`FAILED`、`ALL_CLEAR`。

## 5. 界面设计

### 5.1 图形库与实现边界

基础版只依赖 **Pygame 2.x**，不需要 Tkinter、PyQt、Pillow 或其他 GUI 库混用。

| 能力 | Pygame API | 用途 |
|---|---|---|
| 窗口与标题 | `pygame.display.set_mode`、`set_caption`、`flip` | 创建 `1200 × 800` 主窗口并刷新画面 |
| 游戏事件 | `pygame.event.get`、`pygame.QUIT`、`MOUSEBUTTONDOWN` | 退出、鼠标点击和按钮交互 |
| 图形绘制 | `pygame.draw.rect/line/polygon/circle` | 棋盘、箭头、按钮、爱心和背景装饰 |
| 文字 | `pygame.font.SysFont`、`Font.render` | 标题、HUD、提示和按钮标签 |
| 动画计时 | `pygame.time.Clock`、`clock.tick(60)` | 以 `delta time` 驱动 60 FPS 动画 |
| 矩形与命中 | `pygame.Rect`、`collidepoint` | 组件布局、按钮和棋盘点击判定 |
| 鼠标状态 | `pygame.mouse.get_pos` | 按钮悬停和格子高亮 |
| 音频（可选） | `pygame.mixer.Sound` | 成功、碰撞和通关音效；无资源时不影响游戏 |

箭头、按钮、爱心、棋盘、边框和点击效果均使用 Pygame 图元实时绘制。主题背景 `assets/ui_background.png` 使用 OpenAI 内置图像生成工具原创生成，通过 `pathlib.Path` 加载；素材缺失时自动回退到程序绘制的深色网格背景。

### 5.2 窗口、网格与响应式布局

- 窗口固定按原生 `1200 × 800` 像素绘制，不使用 `pygame.SCALED`，避免二次缩放造成字体模糊。
- Windows 下在创建窗口前启用 Per-Monitor DPI 感知，避免系统显示缩放将整窗位图放大。
- 顶部 HUD：`y=24~104`；主体区域：`y=128~704`；底部提示栏：`y=724~776`。
- 左侧棋盘面板：`x=48~712`；右侧信息面板：`x=744~1152`。
- 棋盘最大绘制区域为 `560 × 560`，居中放置在左侧面板。
- 动态格子边长：`cell_size = min(84, 504 // max(rows, cols))`；6×6 为 `84 px`，7×7 为 `72 px`。
- 棋盘实际尺寸为 `cols * cell_size × rows * cell_size`，不能用固定 4×4 或 5×5 尺寸计算。

建议布局：

```text

│  箭途                第 1 / 3 关          ♥  ♥  ♥       │
├─────────────────────────────────┬────────────────────────┤
│                                 │  关卡：方向热身        │
│                                 │  剩余箭头：12          │
│          6×6 / 7×7 棋盘         │  失误机会：3 / 3       │
│                                 │                        │
│                                 │  [重新开始]            │
│                                 │  [玩法说明]            │
│                                 │  [返回首页]            │
├─────────────────────────────────┴────────────────────────┤
│ 状态提示：请选择一支箭头                                │
└──────────────────────────────────────────────────────────┘
```

### 5.4 字体层级

- 游戏标题：`48 px`，粗体；
- 结果标题：`42 px`；
- HUD 关键数字：`30 px`，粗体；
- 按钮文字：`24 px`；
- 正文与玩法说明：`20~22 px`；
- 状态提示：`20 px`。

字体回退顺序建议为“Microsoft YaHei → SimHei → Pygame 默认字体”。可封装 `load_font(size, bold=False)`，避免每帧重复创建字体对象。若仓库附带开源中文字体，必须在 README 标明名称、来源和许可证。

### 5.5 开始界面

从上到下包含：

1. 游戏标题“箭途”；
2. 副标题“观察方向，按正确顺序让箭头全部离场”；
3. 小型示意棋盘，展示一支被阻挡箭头和一支可飞出箭头；
4. “开始游戏”主按钮；
5. “玩法说明”和“退出游戏”次按钮；
6. 底部显示“鼠标左键操作｜每关只有 3 次失误机会”。

点击“玩法说明”后显示模态面板，解释成功、碰撞、失误和过关规则；按 `Esc` 或点击关闭按钮返回开始界面。

### 5.6 游戏界面与交互层级

游戏界面必须显示：当前关卡、关卡名称、棋盘、剩余箭头数、固定 3 次失误机会及其剩余值、重新开始按钮。

交互层级从高到低：

1. 结果弹窗或玩法弹窗；
2. 右侧按钮；
3. 棋盘箭头；
4. 空白背景。

同一次鼠标点击只允许被最高层组件消费一次。只有鼠标左键按下且命中存活箭头的格子时才调用规则层；右键和空白点击不扣失误。动画期间按钮仍可选择是否保持可用，但棋盘必须锁定，防止重复结算。

### 5.7 结果界面

- 使用半透明遮罩覆盖游戏界面，中央显示 `520 × 360` 的结果卡片。
- 关卡通关：标题“第 N 关通过”，显示本关剩余失误次数，提供“下一关”。
- 最终通关：标题“全部关卡完成”，提供“再玩一次”和“返回首页”。
- 失败：标题“挑战失败”，正文“3 次失误机会已用完”，提供“重新挑战”和“返回首页”。
- 结果层出现后，底层棋盘不可点击；`Enter` 可触发主按钮，`Esc` 返回首页。

### 5.8 反馈与动画

- 成功飞出：箭头在 `300~450 ms` 内沿方向移动到棋盘外，使用 `ease_out_cubic` 缓动；动画结束后删除数据。
- 碰撞反馈：箭头沿方向偏移 `8~12 px` 后弹回，往返 2 次，共 `240~320 ms`，同时闪红。
- 文本反馈：底部显示“成功飞出！”或“路径被阻挡，失误 -1”，约 `800 ms` 后淡出。
- 失误反馈：对应爱心缩小并变灰；从 1 降到 0 时再显示失败弹窗。
- 通关反馈：最后一支箭头移除后等待约 `400 ms` 再显示结果，避免动画被立刻遮挡。
- 动画必须使用 `delta time` 更新，不在主循环中调用阻塞式 `sleep`。

### 5.9 可复用 UI 组件

建议实现以下轻量组件，不引入额外 GUI 框架：

```python
Button(rect, text, on_click, style)
    handle_event(event) -> bool   # 返回事件是否被消费
    update(mouse_pos, dt) -> None
    draw(surface) -> None

Modal(title, body, primary_button, secondary_button)
Hud(level_no, level_name, remaining_arrows, remaining_mistakes)
Toast(message, color, duration_ms)
```

绘制顺序固定为：背景 → 面板 → 棋盘格 → 箭头 → HUD/按钮 → Toast → 模态遮罩与结果卡片。这样可避免弹窗被棋盘覆盖。

## 6. 数据设计

### 6.1 核心对象

```python
Direction = Enum("Direction", ["UP", "DOWN", "LEFT", "RIGHT"])

Arrow:
    id: str
    row: int
    col: int
    direction: Direction
    state: IDLE | FLYING | COLLIDING
    animation_progress: float

Level:
    id: int
    name: str
    rows: int
    cols: int
    arrows: list[Arrow]

GameSession:
    current_level_index: int
    remaining_mistakes: int      # 进入/重开任意关卡时固定为 3
    arrows: list[Arrow]          # 当前关卡的运行时副本
    screen_state: ScreenState
    message: str
```

关键约束：

- `Level` 是只读模板；进入或重开关卡时必须深拷贝，不能直接修改原始关卡数据。
- 全局常量 `MAX_MISTAKES = 3`，关卡数据不得单独覆盖失误次数。
- 箭头 `id` 在同一关内唯一，用于测试、动画和通关顺序描述。
- 规则层使用 `(row, col)`；界面层负责像素坐标与网格坐标的转换。

### 6.2 推荐关卡格式

```python
{
    "id": 1,
    "name": "方向入门",
    "rows": 6,
    "cols": 6,
    "arrows": [
        {"id": "A", "row": 4, "col": 4, "direction": "DOWN"},
        {"id": "B", "row": 3, "col": 5, "direction": "LEFT"},
        # 其余箭头见第 7 章
    ],
}
```

加载关卡时校验：行列为正数、坐标不越界、坐标不重复、方向合法、ID 不重复；开始或重开关卡时另行断言 `remaining_mistakes == MAX_MISTAKES == 3`。

## 7. 预置关卡设计

符号说明：`↑ ↓ ← →` 表示箭头，`.` 表示空格。三个关卡的失误机会均固定为 **3 次**。下列解法不是唯一解，但可作为自动验证和人工试玩的基准。

### 7.1 难度递进指标

| 关卡 | 棋盘 | 箭头数 | 初始可飞出数 | 阻挡依赖数 | 最长依赖深度 | 难度设计 |
|---|---:|---:|---:|---:|---:|---|
| 第 1 关 | 6×6 | 12 | 6 | 8 | 4 | 可选入口较多，学习观察方向和短依赖链 |
| 第 2 关 | 7×7 | 16 | 4 | 16 | 6 | 可选入口减少，出现多条链和前后汇合 |
| 第 3 关 | 7×7 | 20 | 4 | 33 | 8 | 棋盘更密集，一支箭头常被多支箭头共同阻挡 |

“阻挡依赖数”是所有箭头正前方阻挡者数量之和；“最长依赖深度”是从可飞出箭头到最终箭头的最长解锁链。箭头数、依赖数和最长链均逐关增加，因此后续关卡不仅更大，也需要更多步的顺序推理。

### 7.2 第 1 关：方向热身（6 × 6，12 支箭头）

```text
     c0 c1 c2 c3 c4 c5
r0    .  .  .  .  ↑  .
r1    .  .  .  ↓  →  .
r2    .  ↓  .  →  .  .
r3    .  ↓  .  .  .  ←
```

### 7.5 关卡验证规则

每个关卡在提交前都要同时通过：

1. 用规则函数逐步执行参考顺序，确认每一步均不受阻挡；
2. 执行完后剩余箭头为 0；
3. 本人至少完整试玩一次；
4. 重开后布局与失误次数完全恢复；
5. 将参考解法保留在测试数据中，不显示给普通玩家。

### 8.1 核心接口约定

```python
def direction_vector(direction: Direction) -> tuple[int, int]:
    """返回方向对应的 (dr, dc)。"""

def is_blocked(arrow: Arrow, occupied: set[tuple[int, int]], rows: int, cols: int) -> bool:
    """检查箭头正前方到边界之间是否存在其他箭头。"""

def find_arrow_at(arrows: list[Arrow], row: int, col: int) -> Arrow | None:
    """返回指定网格位置的存活箭头。"""

def handle_arrow_click(session: GameSession, arrow_id: str) -> ClickResult:
    """只做规则结算并返回 FLY / COLLIDE / IGNORED，不直接绘图。"""

def reset_level(session: GameSession, level_template: Level) -> None:
    """从模板重新创建当前关卡状态。"""

def validate_level(level: Level) -> list[str]:
    """返回关卡数据错误列表；空列表代表静态校验通过。"""

def screen_to_cell(x: int, y: int, board_rect, cell_size: int) -> tuple[int, int] | None:
    """把鼠标像素坐标转换为网格坐标，棋盘外返回 None。"""
```

### 8.2 事件处理顺序

1. Pygame 主循环接收事件；
2. 根据当前 `screen_state` 将事件交给对应界面；
3. `PLAYING` 状态下先判断重开/返回按钮，再判断棋盘点击；
4. 像素坐标转换为网格坐标；
5. 查找箭头并调用规则层；
6. 根据 `ClickResult` 启动动画或更新提示；
7. 动画完成后再删除飞出的箭头并检查通关；
8. 每帧执行 `update(dt)` 和 `render(surface)`。

## 14. 风险与应对

| 风险 | 表现 | 预防/处理 |
|---|---|---|
| 坐标方向写反 | UP/DOWN 检查错行，边缘越界 | 统一方向向量，用 U01~U08 覆盖四方向和边界 |
| 规则与绘制耦合 | 无法测试，只能靠试玩发现错误 | `rules.py` 不导入 Pygame，只接收模型和坐标集合 |
| 动画期间重复结算 | 一次点击删除多箭或连扣失误 | 动画时锁定棋盘输入，动画结束再改变关键状态 |
| 重开污染模板 | 重开后缺箭头或次数不正确 | 关卡模板只读，运行状态使用深拷贝 |
| 关卡不可解 | 箭头依赖形成闭环 | 保存参考解法，用测试逐步执行并人工试玩 |
| 中文字体缺失 | 文字变方框或不同机器崩溃 | 提供字体回退；附带字体时注明许可证 |
| 素材侵权 | 直接使用商业游戏资源 | 使用代码绘制、自制素材或明确许可的资源 |
| AI 代码不可解释 | 答辩时无法说明关键逻辑 | 每次合并前阅读、运行和修改；博客只放能解释的关键代码 |
| 一次性提交 | Git 历史无法体现过程 | 每个 M 阶段完成后单独 Commit 并推送 |

## 16. 附加功能候选（基础版通过后再选）

按“收益/成本”建议顺序：

1. **提示功能**：高亮当前可飞出的一个箭头；实现成本低，能展示规则复用。
2. **计时与星级**：按用时和剩余失误评分；界面展示价值高。
3. **关卡选择**：仅开放已通过关卡；需要简单进度数据。
4. **撤销一步**：保存操作前快照；要明确是否恢复失误次数。
5. **音效与粒子效果**：增强反馈，但必须处理资源许可。
6. **自动求解/随机可解关卡**：算法价值高，但开发和验证成本最高。

附加功能最高优先原则：不得破坏基础规则、3 个关卡、重开和结果流程。
